### Z10 首轮能力核验

1. 获取设置中的“关于/系统信息”页，以及应用列表或配套手机 App 名称；公开材料遮挡设备唯一编号、账号与凭据。
2. 核实是否有可安装自有应用的系统、SDK 或厂商固件开发渠道；安装方式未确认前不刷机、不重置。
3. 核实是否支持持续 BLE 扫描，能否解析测试信标的 UUID/Major/Minor/RSSI 和采集时间。蓝牙配对、通话或计步功能不能代替这项验证。
4. 核实能否通过 Wi-Fi、蜂窝或配套手机将上述扫描结果传给适配服务；存在联网图标不能代替真实上报样本。
5. 用一枚保留现有身份的信标先测试扫描，再测试锁屏/后台持续采集与断网恢复，记录电量影响。若不支持扫描开发，另核实手表是否有可被固定网关识别并关联人员的广播；不得认定现有信标能接收手表广播。

通过扫描与上报验证后，才确定“固定信标 → 手表扫描 → 适配服务”的实施路线及 UUID 过滤规则。目前 BeaconSET 参数仍是候选方案，未批量修改。

## 当前交付与使用顺序

已根据用户提供的 BeaconSET v2.0.0 手册新增 [BeaconSET 配置方案](BeaconSET配置方案.md) 及首轮配置清单。手册确认可配置 iBeacon 广播身份与参数；不等于确认具体设备型号、手表扫描协议或坐标输出能力。实体信标尚未写入、回读或走测。

1. 填写 `templates/设备登记模板.csv`，确认数据链路。真实设备编号、MAC、网络地址与原始报文仅存本机 `local-private/`（已加入 Git 排除）；模板内不填凭据、姓名、客户资料。
2. 参照 [接口契约](接口契约v0.1.md) 请供应方提供脱敏样本和协议说明。此为项目内部候选契约，未声称厂商支持任何指定接口。
3. 按 [现场标定流程](现场坐标标定流程.md) 采集。只有区域输出时先做房间映射和识别验证；有连续坐标时再执行坐标拟合。
4. 本机验证通过后，开发只读适配与真实模式。首轮范围建议为护理站、2414、2415 及附近走廊，现场确认后执行。

## 第一次与供应方核实的事项

- 手表、信标、网关的品牌型号、数量、固件版本；是否有 SDK、平台或管理后台。
- 谁扫描谁：手表扫描信标后经 Wi-Fi/蜂窝/其他通道上报，网关扫描手表广播，还是其他链路？普通信标是否只有广播能力？
- 当前是否能看到真实设备数据？数据是信标/RSSI 列表、房间标识，还是带单位的连续坐标？不得把 RSSI 强弱直接当作精确距离。
- 本地或云端接口、协议版本、推送/查询方式、鉴权、时间戳、上报周期、离线缓存、重发、授权费用和厂商测试方式。凭据走安全渠道。
- 场地平面图版本、已安装点位、安装高度、供电、网络、现场操作人及可测试时段。
- 呼叫是否来自同一手表/同一平台？手表按键事件是否真的可上报？床头呼叫另行核实。
