# BeaconSET 信标配置方案 v0.1

日期：2026-11-20。依据用户提供的《BeaconSET 用户操作手册》v2.0.0（20 页）。原文件位于本机桌面，不复制进源码仓库。手册是配置软件说明，不是所购信标的具体型号规格。

状态：已完成参数方案及首轮配置清单；尚未连接或写入任何实体信标。当前没有可操作的手机 BeaconSET 会话或蓝牙配置接口。实际配置、回读、手表识别和现场覆盖均待完成。

## 手册明确支持的功能

|项目|手册内容|依据页|
|---|---|---|
|设备识别/过滤|按设备名称或 MAC 过滤；也可扫码查找|4–6|
|UUID|32 位十六进制字符，允许大小写|7–10|
|Major / Minor|均为 0–65535|10–12|
|校验距离参数|-127 至 0，常见 -55、-59；手册建议非专业人员不改|12–13|
|广播功率|从实际设备显示的档位列表选择|13–15|
|广播周期|100 ms 至 10 s；手动输入数值乘 100 才是毫秒数|15–16|
|名称|可修改，手册未给长度上限|17|
|连接模式|YES 可连接，NO 不可连接；NO 存在五分钟可连接窗口|18|
|“重启密码”栏目|新密码长度 8 位；实际界面图亦显示修改密码|18–19|

图 1-29 显示 -20、-16、-12、-8、-4、0、4 dBm 等档位及特定芯片超低档；不保证所购型号全部具备。页面中的“校验距离”是设备参数名称，不能把 -59 解释为距离米数。手册没有提供精确定位算法、扫描上报协议或连续坐标 API。

## 首轮配置策略

先只配置一枚测试信标，回读并确认手表能收到，成功后再逐枚配置。若现场已有平台绑定、UUID 白名单或既有编号，优先保留现有身份，补登记映射，不能直接覆盖为下面的新编号。

|参数|首轮设置|性质与条件|
|---|---|---|
|UUID|优先保留现有；全新系统可用下方候选 UUID|必须先核对手表/平台过滤规则|
|Major|24|新系统中约定表示 24F；不是设备自动定位功能|
|Minor|1、2、3、4|分别分配首轮四枚设备；同一 UUID+Major 下唯一，不因房号相同而复用|
|设备名称|BX24-001 至 BX24-004|便于现场过滤；实际设备长度支持待回读|
|广播周期|500 ms|工程试测起点，不是厂家规定值；优先选列表 500 ms，手动输入则填 5|
|广播功率|-12 dBm（仅实际列表支持时）|工程试测起点，不是覆盖保证；不支持时保留原值并登记，待现场选档|
|校验距离|保持出厂/当前值|记录后不改；不能用它修正房间误判|
|连接模式|YES|首轮需反复连接回读，暂不设 NO|
|密码|使用现场现有凭据保存；本轮不修改|不猜测默认密码，不把凭据写入表格、源码或截图|

新系统候选 UUID：

```text
99472CDD346649E8AB9C8ADFA64F1B51
```

这是本次生成的项目候选标识，不是厂家默认值或已写入设备的值。若手表有固定识别规则，改用兼容值，并同步清单。Major/Minor 只是身份与映射，房间及坐标来自本项目登记。

`templates/BeaconSET首轮配置清单.csv` 中四行是候选设备槽位，不代表已采购数量或实际安装记录。对应 2414、2415、护理站和附近走廊的试测位置，最终安装点、高度和底图坐标现场登记至 `local-private/`。多枚信标服务同一房间时仍须各用独立 Minor。

## 手机逐枚配置操作

1. 打开 BeaconSET，启用蓝牙并按当前系统要求授予扫描权限。核对实体标签和扫描列表，确认没有选到其他门店或旁边设备；不要同时连接同一枚设备。
2. 读取并记录原始 UUID、Major、Minor、名称、周期、功率、校验距离、连接模式和电量（如界面提供）。本机记录置于 `local-private/`，保留恢复依据。
3. 首枚先确认手表是否能看到现有广播，再决定是否启用候选 UUID 和编号。使用新方案时，写入清单对应的 UUID、Major、Minor、名称、周期、功率及 YES；保留校验距离与密码。
4. 按手册逐个参数进入编辑页，点击该页“保存”回详情页，再点击详情页“保存”，在手机上输入现有密码并等待配置成功。不要以仅退出编辑页或仅看到新值作为已写入证据。连接模式等页面最终行为以实际设备回读为准。
5. 断开后重新扫描，核对广播中的 UUID/Major/Minor/名称；重新连接读取周期、功率和校验距离。手册说明后三项不能仅靠断开后的列表验证。
6. 断开配置连接，用实际手表确认能持续扫描到目标身份，记录其采集时间及 RSSI；若当前手表软件无法展示/上报这些数据，停在“信标配置已回读，手表接入待开发”，不能标成定位完成。
7. 第一枚通过后按清单配置其余设备；每枚贴内部编号标签，登记与实际设备的对应关系。配置前后不更换现场安装点，便于比较。

不可连接模式下名称可能显示 Unknown、名称过滤失效；手册还说明某些 iOS UUID 显示受微信 UUID 影响。不要为消除 Unknown 擅自切换全场 UUID，需用 Android 或实际手表/解析器验证识别。连续五次密码错误会触发约五分钟不可连接状态，停止重试并核实凭据。

## 覆盖与房间区分试测

500 ms 是广播设置，不能当成手表扫描/网络上报间隔。后者需手表协议另行确认。

在 2414/2415 房内、门内/门外、走廊和护理站按统一佩戴方式采集，比较目标与邻房信标的可见性、RSSI 分布、未知比例、房间混淆及切换延迟，使用现有区域验证表。初轮可每点采集约 60 秒并重复不同朝向；这只是采样建议，不是验收标准。

优先核对实际安装点和遮挡；每次只改一个参数。覆盖缺失时再逐档提高功率，邻房串扰明显时再逐档降低并复测。实际设备若支持，-12 → -8 → -4 dBm 可作为升档试验顺序，-12 → -16 → -20 dBm 可作为降档顺序，均需记录结果。调整功率后保留校验距离原值只适用于本轮识别试验，不能据此使用未经重新标定的 RSSI 测距。

若手表只上报信标/RSSI，先推进区域定位；不得把信标安装坐标直接当作佩戴者实测坐标，也不得对其套用连续坐标拟合。手表型号、扫描解析和联网协议仍是下一步必需资料。
