# 现场坐标标定与房间识别验证

状态：流程已准备，未采集现场数据。不得将模板或合成测试数据当作实测结果。

## 1. 先确认空间底图

当前页面 `DATA.cx=39.3`、`DATA.cy=11.6`，代码将平面米制 X（东）、Y（南）转换为 Three.js：`worldX=planX-39.3`、`worldZ=planY-11.6`；人物 worldY=0。模型与现场尺寸、方位仍须核对。门框、墙角等标定点必须从实际底图获得平面坐标，不能用人物初始点或家具位置替代测量点。

登记底图版本、测量基准、楼层标识、测量人和日期。信标记录安装位置、高度、朝向、发射配置及编号；是否允许调整配置先依现有现场管理流程确认。

## 2. 若只有信标观测或区域数据

先在 2414、2415、护理站、走廊分别做静止采样和往返穿门测试，记录真实区域、预测区域、时间、是否未知及切换延迟。覆盖门内/门外、相邻房间、人体遮挡和不同朝向，不靠一次 RSSI 最大值决定最终布点。

采用 `templates/区域验证模板.csv`。分别统计各房间识别率、相邻房混淆、未知比例、切换延迟以及离线恢复；门口缓冲区域如何算对需事前约定。不能对只有区域输出的数据运行连续坐标拟合。若仅有 RSSI，房间判定算法和参数需另行实现、采样验证。

## 3. 若有连续坐标

使用 `templates/标定点模板.csv`，每行一个已汇总的标定点。`source_x/source_y` 使用供应方统一单位；`plan_x/plan_y` 使用底图米制坐标。

- 至少 3 个分散且不共线的 `fit` 点，用于求比例、旋转和平移；另设至少 2 个未参与拟合的 `check` 点。实际优先采集更多分散的检查点，不能把全部点用来拟合后报告为验证。
- 点位建议覆盖护理站、走廊远端、房门内外及公共区；具体坐标必须现场测量。避免都在一条走廊中线上。
- 每点按统一佩戴方式静止采样，记录原始时间序列、样本数、采样时段及散布；汇总坐标可以用中位数，不能只挑最贴近底图的样本。
- 先统一源坐标轴方向。工具支持显式 `--flip-y` 镜像；只有确认轴向需要时使用，不能为降低误差盲试。默认拟合二维相似变换，不支持剪切、非等比缩放和自动镜像。

运行示例（真实数据置于被 Git 排除的本机目录）：

```sh
python3 tools/calibrate_location.py local-private/points.csv --max-check-error-m 1.0 --output local-private/calibration.json
```

`1.0` 仅演示参数写法，不是已约定的验收指标。工具要求调用者显式指定检查点最大误差阈值，输出每点误差、拟合 RMS、检查 RMS 和最大检查误差；不通过返回非零退出码并仍输出诊断报告。结果始终只代表这些汇总点的几何误差，不是动态定位精度或全场验收。

## 4. 独立走测与验收

完成静态转换后，佩戴真实手表往返走过护理站—2414—2415—走廊，在底图记录实际路线与时间。记录端到端延迟、静止漂移、门内外误判、相邻房混淆、数据丢失、断网与恢复，以及手表换绑。

验收指标待双方确认：覆盖范围、静态/动态 P50/P95 位置误差、各区域识别率、房间切换延迟、端到端时延、过期阈值、丢失与恢复表现。几何检查通过不能替代这些测试；不满足房间区分要求时，应回到安装、定位能力或算法分析，不能只靠画面平滑掩盖。
