# 定位接口契约 v0.1（候选，待厂商确认）

本契约描述适配服务向数字孪生输出的数据，不是已存在的服务地址。优先复用现有系统，拿到厂商原始协议后填写映射，不要求硬件直接实现本契约。

## 数据链路与能力分支

设备/网关 → 厂商平台或采集服务 → 适配服务 → 3D 页面。

- `coordinate`：源系统提供经过定义的平面坐标；适配服务完成单位、轴向、楼层及坐标标定转换。
- `zone`：源系统仅提供区域；展示区域归属，展示点不得标成精确实测位置。
- `observation`：只有信标扫描/RSSI。先保存脱敏观测样本，验证房间识别算法及覆盖，不能直接生成可靠坐标。算法暂未选定。

## 建议内部消息

以下完全为虚构样例，`siteId`/`floorId`/区域标识须由项目统一登记。

```json
{
  "schemaVersion": "0.1",
  "eventId": "example-event-001",
  "sourceId": "example-platform",
  "streamId": "example-boot-001",
  "sequence": 12,
  "occurredAt": "2026-11-20T10:00:00Z",
  "receivedAt": "2026-11-20T10:00:01Z",
  "type": "location.updated",
  "siteId": "gaoxin",
  "floorId": "24F",
  "deviceId": "watch-example-001",
  "bindingVersion": "example-binding-1",
  "data": {
    "mode": "coordinate",
    "position": {"x": 10.0, "y": 12.0, "unit": "m", "frameId": "gaoxin-24f-plan-v1"},
    "zoneId": null,
    "calibrationId": "example-calibration-001",
    "accuracyM": null
  }
}
```

- 时间为带时区的 RFC3339 UTC；`occurredAt` 是采集时间，`receivedAt` 是适配服务接收时间。设备无可信时钟时，需增加 `timeQuality`，标明使用网关时间或接收时间，不能伪造测量时间。
- `eventId` 在来源范围内唯一，用于去重；适配层需有明确的重发去重策略。`sequence` 若源端不提供应为 null，不能把适配端接收序号当作源端测量顺序。重启由 `streamId` 区分。
- `deviceId` 使用内部不透明编号。人员绑定独立保存生效起止时间、岗位和绑定版本；晚到事件按采集时的有效绑定解析，避免换表串人。不能把 MAC 当人员身份。
- `coordinate` 必须包含有限数值坐标、单位、坐标系版本和标定版本；本楼层只处理二维定位，网页人物高度为展示设定。
- `zone` 必须包含有效 `zoneId`，`position` 为 null。缺失楼层/未知设备/未知区域不得默认填成某个房间，须进入待核对状态。
- `accuracyM` 只在有明确来源和含义时填值，否则 null。不把 RSSI 直接换成精度声明。
- `observation` 原始字段至少核实扫描设备、被扫描信标标识、RSSI 单位、采集时间、扫描窗口；仅供后端算法，默认不广播到普通前端。
- 电量/连接状态使用独立 `device.status`，字段为 `batteryPct`（0–100 或 null）、`lastSeenAt`、`connectivity`。连接在线与位置新鲜度分开判断。

## 初始状态与实时流

建议逻辑资源为“楼层快照”和“楼层事件流”；HTTP、WebSocket、SSE 或轮询须依现有软件能力选择，目前无已部署端点。

- 快照返回当前人员绑定、最新位置、设备状态、服务器时间和游标。
- 快照对应游标之后订阅增量，避免初始化丢事件。服务端不支持游标回放时，重连必须重新拉取完整快照并采用明确的快照/流同步机制。
- 以事件唯一键去重；同一设备同一流按源序号处理；无可靠序号时使用可信采集时间并明确同时间冲突策略。旧事件可留作历史，不覆盖更新位置。
- 心跳、过期阈值、重连退避及回放保留期须按实测上报周期填写；尚未设置生产默认值。过期后停止移动、标明最后更新时间，不能继续模拟。
- 前端只对有效相邻坐标做有限插值，不做无限外推。异常跳点/越界保留原始诊断信息，标为待核对，不能自动改成“合理”实测轨迹。
- 接收端对枚举、有限数值、时间、设备绑定、门店/楼层权限及消息体大小进行校验；异常消息隔离，不中断整条数据流。

## 权限与业务边界

厂商密钥仅放服务端安全配置；远程传输使用加密连接。前端由现有登录授权限定门店、楼层和人员可见范围。原始轨迹及人员绑定的留存、查看和导出权限须由业务负责人确认。

首期只读。呼叫由独立 `callId` 串联发起、接单、处理中、完成/取消事件，实际状态映射等待现有业务协议。定位到达房间不自动等于接单或完成，位置也不能证明喂奶、洗澡等动作。
