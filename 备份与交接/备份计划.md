# 备份计划

项目：伴月轩数字孪生高新店。专用私有仓库 `Alston3825/banyuexuan-digital-twin-gaoxin`，中文名称已写入 GitHub 描述及仓库首页，不另建重复仓库。

## 调度与责任

- 固定时区 **America/Los_Angeles**，每日 **03:00、09:00、15:00、21:00** 四次。夏令时按 IANA 时区计算，不硬编码与北京时间的时差。
- 本聊天 Codex 自动任务负责读取开发进展/用户决定、维护交接说明、执行检查点并检查失败；已有 launchd 五分钟源码同步与登录补跑继续保留，作为两次检查点之间的增量保护。
- 四个时间点是计划，不是保证执行。Mac、用户会话、Codex 和网络须可用；停机/休眠/离线可能迟到或漏跑。恢复后核对最近实际成功时间并补做当前检查点，不编造过去的版本或四次上传记录。

## 一轮执行

1. 读 AGENTS.md、交接说明、当前任务、服务器状态和最新修改。核对“已实现/测试通过/实机通过/已部署”的区别，更新交接中的最新证据和未完成项。
2. 运行 `python3 tools/backup_checkpoint.py`。脚本与旧同步器使用同一 sync.lock；若有其他备份占用则明确退出，稍后重试。
3. 索引、每日交接、源码和资料一起写独立镜像，不修改原工作区 Git 分支、未提交修改或历史。镜像校验关键文件、文件数骤减、文件哈希、大文件及疑似令牌；触发保护则停止，不能用空目录覆盖远端。
4. 非 force 推送 main；核对远端 SHA，再推送并核对 `checkpoint/实际日期-实际时间-微秒` 标签。任何步骤失败不登记本轮成功；日志与自动任务报告保留失败原因。网络失败时仅对相关进程取消失效代理重试，不改系统网络设置。
5. 成功状态在本机 `~/.banyuexuan-project-sync/digital-checkpoint-status.json`。同时查看实际 checked_at，不能只看 result=ok。

## 留存与恢复演练

main 始终为最近安全快照，Git 历史及四次任务实际执行的 checkpoint 标签持续保留，不自动清除历史。每日交接目录保留每日最终快照，同日多版从 Git/标签取回，避免每天复制全部 Blender 资源。

每周核对调度失败、最近成功时间和排除范围；每月至少一次从 GitHub 独立 clone 至临时目录，执行 `python3 tools/verify_backup.py`、场景资源校验和单元测试；每次备份规则变更立即做独立恢复演练。未经允许不对生产库做恢复测试。

恢复顺序：授权账号 clone → 选择 main 或 checkpoint → 校验 SHA256 → 读交接与最新记录 → 安装开发依赖 → 本机预览/测试 → 安全取得缺失配置/资料 → 经明确授权后才涉及真实部署或业务数据恢复。

## 安全及容量

范围见 `资料覆盖清单.md`。GitHub 中不放真实配置、私钥、客户资料和运行数据；大于 99 MiB 单文件停止上传后另定存放方案，不静默丢弃。压缩包、依赖、构建缓存不当作源码提交。GitHub 访问凭据由用户原安全配置管理，账号应保留独立恢复手段；源码私有仓库不能代替独立加密生产备份。
